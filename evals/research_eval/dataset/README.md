# Question set

`questions_v0.jsonl` is a **placeholder** to exercise the pipeline end to end;
the real set's size and composition are still open. Bump the file version
whenever questions change: the version is recorded in every run archive.

Each line: `question_id`, `question`, `report_type`, and the `modes` to run it
in (`default`, `detailed`, `deep`).

`key_points/<question_id>.json` (optional) freezes a question's key points:
`{"aspects": [{"aspect": "...", "sub_points": ["...", "..."]}]}` (the older
`{"key_points": ["...", "..."]}` without sub-points is still read). When
present it is used instead of the cached judge output. Without frozen files,
re-scoring without the cache regenerated the lists and moved comprehensiveness
and decomposition coverage by up to 0.29 between reps.

`key_points/q001.json`–`q005.json` were written on 2026-11-08 by the method
`key_points.py` uses (3 `key_points_layered` v3 drafts merged by
`key_points_synthesize` v1, judge gpt-6-luna) and frozen as they came. Not yet
reviewed item by item.

`rubrics/<question_id>.json` (optional) freezes a question's insight and
readability rubric: `{"insight": [{"criterion", "description", "weight"}],
"readability": [...]}`. When present it replaces the rubric judge call.
Regenerated on every cache rebuild, the rubric differed for 15/15 questions
between two passes and moved insight by up to 0.13.

`rubrics/q001.json`–`q005.json` were generated by the judge (quality_rubric
v3) on 2026-11-07 and frozen as they came, except q004's "Clear scope",
which lost "or unsupported uses of the word 'leader'" (accuracy is not
readability). Not yet reviewed item by item.
