# 报告语言切换功能设计

## 目标

在 Next.js 前端的 Preference 设置中增加中文和英文两种报告语言，并将用户选择传递到标准研究、深度研究和详细报告流程。生成的报告正文应使用本次任务选择的语言。

本次修改不负责翻译整个应用界面，也不处理 PDF 中文字体。

## 用户体验

Preference 设置中增加“报告语言”选项，包含：

- 中文（简体）
- English

默认选择“中文（简体）”。新用户以及本地尚未保存语言设置的已有用户都会使用中文。

语言选择与现有设置一起保存在浏览器的 `chatBoxSettings` 本地存储中。用户修改语言后，只影响之后新建的研究任务，不改变已经生成或正在生成的报告。

界面显示值为“中文（简体）”，发送给后端的代码值为 `Chinese (Simplified)`；英文对应的代码值为 `English`。现有报告提示词已经会根据配置的语言生成内容，因此不需要为中文单独复制一套提示词。

## 数据流程

1. 为前端的 `ChatBoxSettings` 类型增加 `language` 字段。
2. 桌面端和移动端的初始设置都将 `language` 默认为 `Chinese (Simplified)`。
3. Preference 表单负责修改并持久化语言选择。
4. 前端通过 WebSocket 发送 `start` 消息时携带 `language`。
5. 前端直接调用 REST 报告接口时也携带 `language`。
6. 后端的 WebSocket 参数解析器和 REST 请求模型接收可选的 `language`。
7. 报告执行器把 `language` 传递给 `GPTResearcher`。
8. 当任务提供了合法语言时，`GPTResearcher` 为当前实例覆盖 `cfg.language`。
9. 现有报告生成提示词继续读取 `cfg.language`。

## 兼容与校验

- 应用请求只允许 `Chinese (Simplified)` 和 `English` 两个值。
- 任务级语言优先于服务器 `.env` 中的 `LANGUAGE`。
- 如果请求没有携带语言、语言为空或语言值不受支持，则忽略该任务级设置，继续使用 `.env` 或 `Config` 中的语言。
- `language` 是可选参数，因此不携带该字段的已有 API 调用仍能正常运行。
- 多个研究任务各自保存语言，不修改全局环境变量，避免并发任务互相影响。

## 异常处理

后端在请求边界校验语言值。不支持的值不会直接写入提示词，也不会导致研究任务崩溃，而是回退到服务器当前配置的语言。

## 测试范围

- 前端测试确认语言字段默认值为 `Chinese (Simplified)`。
- Preference 测试确认中文和英文可以切换并保存。
- WebSocket 测试确认新研究任务会发送 `language`。
- REST 请求测试确认直接创建报告时会发送 `language`。
- 后端测试确认合法值可以通过、不合法值会回退，以及任务级语言优先于环境配置。
- 集成测试确认中文任务中的 `researcher.cfg.language` 为 `Chinese (Simplified)`。
- 回归测试确认未传语言的已有调用继续使用环境配置。

## 不在本次范围内

- 翻译按钮、进度消息等整个应用界面
- 为 PDF 导出安装或配置中文字体
- 翻译搜索到的网页内容
- 修改搜索引擎的地区或搜索语言参数
- 修改独立的多 Agent 实现；该流程暂时继续使用环境变量 `LANGUAGE`
